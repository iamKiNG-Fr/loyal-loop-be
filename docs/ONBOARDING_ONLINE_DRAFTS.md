# Online onboarding drafts — Batch 76

MB-7601 addresses source report 5 in the Loyal Loop Issues Google Doc (page 1). Registration previously kept its editable draft only in localStorage.

The existing signed, HttpOnly invitation grant now authorizes GET/POST `/founding-circle/onboarding-draft`. Each request rechecks invitation status, expiry and use count. The server accepts only bounded, editable form fields, encrypts them with AES-256-GCM and binds the ciphertext to the invitation ID. Passwords, OTPs, verification challenge IDs, media and arbitrary client fields are excluded. Cross-device resume requires opening the same valid invitation; password entry and fresh verification remain enforced by the existing registration transaction. Open registration without an invitation retains the existing device-only fallback.

Writes use an integer revision and conditional update so stale devices, revocation and completed registration cannot overwrite the draft. The client serializes autosaves, coalesces typing, retries failed saves on subsequent edits or explicit retry, and offers an explicit online-version choice when unsynced device changes conflict. Local storage remains a fallback; online resume also works when device storage is unavailable. Saves flush on navigation/backgrounding with fetch keepalive, and successful registration stops pending writes.

Editable drafts remain available for at most seven days after the last save and never beyond invitation expiry. Redemption/revocation clear ciphertext. Expired draft reads clear their own blob, and the existing retention scheduler reports/clears expired blobs when its reviewed enforcement flag is enabled. Retention enforcement is not activated by this change. Progress timestamps and furthest saved step remain as operational invitation metadata; admin responses/audit snapshots exclude draft ciphertext. The admin invitation list displays factual saved progress and actual redemption, without interpreting inactivity as confirmed abandonment. Optional analytics consent is unchanged.

Deployment requires the additive `20260914000000_onboarding_online_drafts` migration before the API and frontend. No database migration has been applied by this batch. Prisma validation and an offline schema-to-schema diff confirm only the six intended columns and expiry index; the normal isolated migration rehearsal and release acceptance remain required before production rollout. Existing invitation encryption/grant keys remain in use; no secrets were changed.

Verification: backend 258/258 tests and production TypeScript build pass. Draft tests cover a fresh grant, field exclusion, ciphertext binding, stale revisions, monotonic progress, missing/forged/revoked/consumed/expired grants expiry cleanup, and atomic completion/late-save rejection. Frontend tests cover serialized/coalesced requests, retry, conflict, cancellation and choosing between online/device drafts. See the frontend Batch 76 record and root backlog for browser acceptance/checkpoints.
